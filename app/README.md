# Gaurav.OS — app

The rebuilt portfolio: React 19 · TypeScript · Vite 7 · React Router 7 (static prerender) ·
Tailwind CSS 4 · three.js + React Three Fiber · GSAP. Every route is prerendered to static
HTML, so it runs on any static host with no server and no Lovable dependency.

**Status: built and tested on branch `claude/beautiful-goldberg-radrlu`. Not deployed.** Full results: `audit/PHASE-2-9-REPORT.md`.

**Preview without deploying:** PR → Checks → *app-ci* → Artifacts → `site-preview`, or build locally (below).

## Run it

```bash
cd app
npm ci
npm run dev          # http://localhost:5173
```

```bash
npm run build && npm run preview   # production build, served at http://127.0.0.1:4173
```

## Test it

```bash
npm run typecheck
npm test               # unit, content-validation and component tests (Vitest)
npm run test:e2e       # 10 user journeys + zero-dead-control crawler (Playwright; needs a build)
node scripts/inventory-report.mjs   # -> reports/interaction-inventory.md
npm run lighthouse     # -> reports/lighthouse/summary.md (needs a build)
```

## How it is organised

```
app/
├── src/
│   ├── content/        every fact on the site — typed, sourced, status-labelled
│   │   ├── profile.ts  experience.ts  projects.ts  capabilities.ts  kb.ts  districts.ts
│   │   ├── sources.ts  types.ts  nav.ts  routes-manifest.ts  data.ts  corpus.ts
│   ├── data/generated/ built from site/content.js + site/corpus.js (never edited by hand)
│   ├── lib/            search, Ask Gaurav engine, PM calculations, analytics, SEO
│   ├── components/     design system (ui.tsx, Icon.tsx), shell, tools/, explore/
│   ├── routes/         one file per route
│   ├── app.css         design tokens (Tailwind @theme)
│   └── root.tsx  routes.ts
├── scripts/            prepare-data, postbuild, serve, build-cv, lighthouse, screens, inventory-report
└── tests/              unit/ (Vitest)  e2e/ (Playwright)
```

- **Changing a fact** means editing `src/content/*`. No component holds content.
- **The 90-day corpus** stays generated: `scripts/prepare-data.mjs` reads `site/corpus.js`
  (itself generated from the case-study repository) and `site/content.js`, applies the
  documented corrections in `CORRECTIONS`, and fails the build if a superseded claim
  (old MCA institution, a phone number, "validated the MVP", "SHIPPED" for GharGyaan) reappears.
- **The brand assets** come from `../brand/assets` (generated by `brand/tools/generate_assets.py`).
- **The CV PDF** (`public/media/gaurav-kumar-singh-cv.pdf`) is printed from the `/cv` route by
  `npm run cv` after a build. It refuses to write a file containing a phone number.
- **3D** is in its own chunk, loaded only by `/explore` on capable desktops. Recruiter Mode and
  every content page ship zero WebGL.

## Content workflows

| Task | How |
|---|---|
| **Replace the portrait** | Put the photo in `public/media/portrait/`, set `profile.portrait.src` (and `provenance`) in `src/content/profile.ts`. Set `src: null` to show the brand mark. |
| **Approve a screenshot** | In `brand/screenshot-review/approvals.json` set `"approved": true` (optional `caption`), then `node scripts/screenshot-review.mjs`. Approved screens appear on that project's case study, labelled “Demo data”. Review sheet: `brand/screenshot-review/index.html`. |
| **Update the research text** | Change the commit in `case-studies.lock.json`, then build. `scripts/build-studies.mjs` renders README + ASSUMPTIONS for all 90 studies, redacts the owner's phone number, and fails if text is lost. |
| **Re-encode the intro film** | From the original `docs/media/gaurav-os-intro.mp4`: AV1 `ffmpeg -i in.mp4 -c:v libsvtav1 -preset 8 -b:v 420k -g 240 -pix_fmt yuv420p -svtav1-params tune=0:rc=1 -c:a aac -b:a 48k -ac 1 -movflags +faststart gaurav-os-intro-av1-1080p.mp4`; H.264 two-pass at `-vf scale=1280:-2 -profile:v high -level:v 3.1 -b:v 400k`. |
| **Measure** | `npm run lighthouse`, `node scripts/film-cost.mjs`, `node scripts/mermaid-audit.mjs` (each after a build). |

## Environment variables

| Variable | Used at | Purpose |
|---|---|---|
| `VITE_SITE_URL` | build | Public URL. Enables canonical URLs, `og:url`/`og:image` and `sitemap.xml`. Omit for local builds. |
| `BASE_PATH` | build + preview | Path prefix, e.g. `/portfolio/` for a GitHub project site. Default `/`. |
| `CHROME_PATH` | tests, CV, Lighthouse | Optional Chromium binary; otherwise Playwright's own. |

No secrets, API keys or server-side credentials exist or are needed.

## Deploying (requires approval — nothing deploys automatically)

**Option A — GitHub Pages (`.github/workflows/app-deploy-pages.yml`, manual).**
1. Repository Settings → Pages → Source: **GitHub Actions** (today it is "deploy from branch `main` `/docs`").
2. Actions → *app-deploy-pages* → Run workflow. Defaults build for `https://gaurav-product.github.io/portfolio` with `BASE_PATH=/portfolio/`.
3. Switching the Pages source replaces the current `/docs` site at that URL.

**Option B — Cloudflare Pages / Netlify / Vercel (static).** Root `app`, build `npm ci && npm run build`,
output `app/build/client`, env `VITE_SITE_URL=https://<domain>`. Unknown paths should serve `404.html`.

**Custom domain** (e.g. moving `gaurav-os.lovable.app` traffic): point the domain at the chosen host,
build with `VITE_SITE_URL=https://<domain>` and `BASE_PATH=/`.

## Rollback

- Nothing on `main` or on Lovable was changed. The current GitHub Pages site (`/docs` on `main`) and
  `gaurav-os.lovable.app` keep working untouched.
- To discard the rebuild: delete the branch, or `git revert` its commits.
- After a Pages cut-over: Settings → Pages → Source back to "Deploy from a branch → `main` → `/docs`".
- After a custom-domain cut-over: point DNS back at Lovable.
